# Setup, voices, fonts and the rarer commands

Read this when `SKILL.md` is not enough: a machine to set up, a voice other than the default, a language other than English, a font, a video file, a web player, a talk as one file.

## Setup

- `visotalk <command> doc.tsx` is the CLI, an npm package: run it as `npx visotalk@latest <command> doc.tsx` (keep `@latest`: a copy installed earlier would run instead, and one older than 0.2 has no `doctor`), or install it once with `npm i -g visotalk@latest`
  (in the repository: `pnpm visotalk`). Node 22.12 or later and `ffmpeg` are needed. Work files go to `.visotalk/<meta.id>/`.
- Run `visotalk doctor --fix` once on a machine before anything else. It reports what rendering needs and installs what is missing into
  `~/.visotalk` (the pinned Chrome, the Kokoro narration model, a Python environment with its packages, the word-timing weights, the fonts; about 1.1 GB, a few
  minutes) so that every command finds them. It cannot install `ffmpeg` or Python 3.9+; it says so and you install those. It exits 0 when all is
  ready. Run `visotalk doctor` to check without installing. `VISOTALK_CHROME`, `KOKORO_DIR`, `VISOTALK_PYTHON`, `TORCH_HOME` and `VISOTALK_FONTS` override what it
  installed; `VISOTALK_HOME` moves `~/.visotalk` (keep it short: narration fails under a path over about 90 characters).
- **Another voice.** The narration is Kokoro unless the document names a provider: `<Doc voice="minimax:English_Trustworthy_Man" speed={1}>` speaks it with MiniMax
  (`MINIMAX_API_KEY` in the environment, which every command reads: never write a key into a command line or a file, and never print it; `MINIMAX_GROUP_ID` and `MINIMAX_TTS_MODEL` are optional; the endpoint is the international `https://api.minimax.io`, so a China account sets `MINIMAX_BASE_URL=https://api.minimaxi.com`), whose word times replace the aligner's for languages
  written with spaces. Also built in: `elevenlabs:<voice id>` (`ELEVENLABS_API_KEY`), `volcengine:<voice_type>` (`VOLCENGINE_APPID` and `VOLCENGINE_ACCESS_TOKEN`; the
  strongest Mandarin) and `openai:<voice>` (`OPENAI_API_KEY`; no word times, so the English-only aligner places the words). Any other service is a module whose default export is `(request) => {audio, ext, words?}`: `voice="./my-voice.mjs:name"`
  (see the header of `packages/cli/src/voice_lines.ts`). A clip is billed once; it is cached by provider, voice, speed, language and text.
- **Choosing a MiniMax voice.** Take one of the document's own language (`lang` `en` → `English_*`, `zh` → `Chinese (Mandarin)_*`, `ja` → `Japanese_*`, `ko` → `Korean_*`), never one of another language, and a broadcaster, announcer or host: steady and knowledgeable. Never a character persona (a princess, knight, queen, butler, boss, girl, boy or lady of some kind). The defaults, from MiniMax's system voice list:
  `English_Trustworthy_Man` (alternative `English_Gentle-voiced_man`), `Chinese (Mandarin)_News_Anchor` (alternative `Chinese (Mandarin)_Male_Announcer`), `Japanese_IntellectualSenior`, `Korean_IntellectualSenior`. A voice that is not in that list is only a guess: `English_captivating_female1`, once named here, does not exist.
- **Chinese, Japanese and Korean.** Kokoro speaks English only, so a document in `lang` `zh…`, `ja…` or `ko…` must name a provider's voice, e.g. `<Doc lang="zh-CN" voice="minimax:Chinese (Mandarin)_News_Anchor">`;
  without one `prepare` stops and says so (and `init` takes `"voice"` in `lines.json`). The lines are timed from their characters (about 4.4 a second in Chinese, measured; Japanese ran at about 5.0 on one script, so write fewer characters than the estimate suggests) until the provider has spoken them, and word
  anchors then use MiniMax's time for each character (Korean is spaced: its word times place the anchors, and a phrase may span words); a voice that returns no times leaves them at the character position, up to half a second off. Write each phrase long enough to occur once. Write numbers as characters in the line, not digits (four hundred and fifty, spelled in Chinese characters).
- **Fonts.** `doctor --fix` installs Noto Sans SC, Noto Sans JP, Noto Sans KR, Noto Serif SC, LXGW WenKai (a kai, brush-script face), Newsreader (a display serif with its italic) and the built-in styles' faces (Caveat, Shantell Sans, Atkinson Hyperlegible Next, Big Shoulders Display, Hanken Grotesk); Inter and JetBrains Mono come with every player. A CJK document gets the Noto Sans of its language by itself, beside any Latin face it names; to choose
  another, name its family in the theme: `<Doc theme="visotalk/dark" tokens={{fonts: {sans: '"Noto Serif SC", serif', mono: '"JetBrains Mono", monospace', display: '"Caveat", cursive'}}}>`. `build` embeds each face cut down to the
  characters the document holds, so a frame does not depend on the machine's fonts; `var(--vt-sans)` and `var(--vt-display)` in a part, and the captions, use them. A face a part names in quotes (`fontFamily: '"Noto Serif SC", serif'` for headings) is embedded beside them. A face the machine lacks stops `build` and names `doctor --fix`; a family no player carries is named by a `font.unavailable` warning, since each viewer would see their own machine's stand-in.
- **Captions.** `tokens.caption` sets their look: `font` (`sans`, `display` or `mono`), `size`, `weight`, `color`, `background` (`'none'` for no box), `radius`, `padding` ([vertical, horizontal]), `bottom`, `maxWidth`, `shadow`, and a `rule` colour with `ruleSide` (`top` or `left`). A style writes it; `validate` names a wrong field.

## More commands

| Command | Does | Cost |
|---|---|---|
| `render doc.tsx [--theme visotalk/light] [--scale 2] [--concurrency N] [--png] [--gpu]` | the video of the first output, or of the one named: `.visotalk/<id>/out/final.mp4` (roughly 3 to 8 s per second of video on four cores; `--scale 2` paints the same layout at twice the pixels, 3840 x 2160 for 16:9, and a `<canvas>` part sizes its backing store by `devicePixelRatio` to stay as sharp; it renders with as many browsers as the machine's cores and memory and the frames allow (30 each, at most 16; it says how many, and `--concurrency N` chooses), its frames go to the encoder as JPEG (`--png` for PNG, with `--frames` to keep them), it renders in segments of 3000 frames, kept in `out/segments/` until the video is joined, so the same command run again after an interruption skips the segments already done (segments made with another document, option or Chrome stay beside and are not used), and `--gpu` draws on the machine's GPU when Chrome reaches one, which it says in its log, at the cost of pixels that differ from machine to machine). It needs the real narration, and stops while an animation names a target no part registers. Captions are painted on the picture unless the document says `exports={{captions: 'sidecar'}}`: then they are left off it (and off the player) and written as `out/captions.srt` (five words a cue), the track to upload with the video; `'words'` paints the spoken words as a block in the lower half of a tall (9x16) frame, each word appearing as it is said, so keep the pictures in the upper half (y 160 to 980 of 1920) | minutes |
| `play doc.tsx` | the interactive web player | |
| `export doc.tsx [--out talk.visotalk] [--cover pic.jpg] [--player]` / `import talk.visotalk [dir] [--remix]` / `play talk.visotalk` | the talk as one file (the document, the files it uses, its narration when prepared, captions, credits) and back into a new directory; an imported talk is checked like any document and nothing in it runs. `--player` makes the built talk instead (it needs the narration; it plays, with no document in it) and `play` serves such a file as a page. A voice module (`voice="./x.mjs:…"`) is code that runs with your keys: `import` refuses it unless you read it and pass `--allow-voice-module` | seconds |
| `build doc.tsx --artifact [--out DIR]` | the player for a Claude artifact: the narration and the sounds mixed into one MP3, as `render` mixes them, the faces the document names or its CJK default embedded as files beside the page (otherwise the system's font), `player.html` (the page) and `artifact.json` (the files to publish with it). Publish it with the Artifact tool instead of rendering an MP4 when you only need to look at the result | seconds |

**Another language** of a document is `doc.<lang>.json` beside it (`references/markup.md`, "Languages"): every command but `export` takes `--lang en` and works on the document in that language, with its own narration in `.visotalk/<id>-<lang>/`.

`sheet`, `still`, `qa` and `render` each use Chrome and take turns: one started while another is running prints `waiting for another visotalk run to finish with Chrome` and waits, so run them one after another, not in parallel, and give each a tool timeout of minutes, not seconds. `--out` of `still`, `sheet` and `qa` is a .jpg (or .png) name inside the document's work folder (`.visotalk/<id>/`), or an absolute path. Let the narration finish (`init` and the first `sheet`, `still` or `qa` start it in the background; `prepare` runs it in front) before the first `qa`: until then every line is timed from its words, so `qa` reports `align.estimated` and the timings it checks are estimates.

`build`, `play`, `qa`, `render` and `sheet` run `prepare` first whenever `KOKORO_DIR` (or `--tts-models`) is set; clips are cached, so it
is quick when no line changed. Without a model they reuse the existing `voice.json` and say so.
